# ipostudio 实现路线图（子项目拆分）

> 依据 writing-plans 技能的 Scope Check：规格覆盖 26 个功能域，单一计划无法保持任务质量。
> 拆分为多个**子项目计划**，每个计划独立交付可运行、可测试的软件，并在 `docs/superpowers/plans/` 下各成一份文档。
> 依赖关系自上而下；同一阶段内顺序可调。每项标注覆盖的规格章节与测试场景（第 18 节编号）。

## 里程碑 M0′：最小可用闭环前置（用户 2026-10-03 批准 UC-1 重排）

**P1 完成后立即执行 P1.5 垂直切片**（原为 P2 入口条件，经用户批准前移为正式子项目）：
安装 llama.cpp → 下载一个小型 GGUF（一次性脚本，非 P2 完整下载器）→ 完成一次补全 → 落日志与 SQLite 记录 → 重启后记录仍在。限时（建议 ≤2 天人工等效）；切片结论回写本文件——若切片失败，先修路线图再继续 P2。

## 里程碑 M0：完整最小闭环（P4 完成即验收）

下载模型 → 引擎实例 → **经网关**完成一次对话 → 持久化记录 → 重启可查。M0 之前的一切质量打磨以此为债务上限（超出 M0 路径的精良实现记入 TODOS 押后）。

**候选楔子功能（CEO 双声部建议，最终命名待用户后续确定）**：① docparse 文档管线 + 知识库（R2 用户指令天然强调）；② 多引擎统一网关（OpenAI/Anthropic/MCP 兼容）；③ 跨工具长期记忆。公开评测/发布叙事围绕三者组织。

## 横切约定（所有计划继承）

- **三平台支持**（需求附录 R1）：Windows/Linux/macOS 为一级目标；CI 三平台矩阵（P1 Task 9 建立后）必须全绿；平台差异点见 `architecture.md` ADR-010。
- **文档格式**（需求附录 R2）：OOXML/ODF 经 `docparse` 解析器注册表进入知识库/OCR/会议纪要；传统二进制格式明确提示转换（ADR-009）。
- 规格验收标准 15：对外文案统一 `ipo`/`ipostudio` 命名。
- 每份计划的 Global Constraints 复制规格对应章节的硬性数值（默认端口、上限、超时）及需求附录 R1/R2 的适用条目。
- 洁净室约束（见 `architecture.md` §0）对所有计划生效。
- 状态机字面量一律取规格 §10.2。
